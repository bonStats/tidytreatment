Scope

This document compares causal-effect estimation across three packages:

  • BART
  • bartCause
  • stochtree

Packages engines bartCause::bartc and stochtree::bcf have in-built propensity score estimation, whilst BART::wbart/BART::pbart and stochtree::bart do not. The former two engines can also be passed an estimated propensity score. We test a DIY propensity score estimation procedure for every engine as well as the in-built procedures where applicable.

The DIY propensity (using fit_diy_propensity()) estimation has two versions:

  • two_stage: variable selection first, propensity fit only on the selected variables (matching the vignettes).
  • ps_all: propensity fit on every confounder directly, with no selection step.

Data generating process

The data-generating process is simulate_su_hill_data() (Hill and Su 2013), used in a continuous version and a binary version (thresholded at the median). Each version is tested under two settings:

  • response_parallel = TRUE (homogeneous treatment effect)
  • response_parallel = FALSE (heterogeneous treatment effect).

Estimated signal-to-noise ratio (continuous case)

Code 
set.seed(1)

sim_snr_het <- simulate_su_hill_data(n = n_snr, tau = 4, response_parallel = FALSE, y_sd = params$y_sd)
snr_par <- var(sim_snr_par$mean_y) / params$y_sd^2
snr_het <- var(sim_snr_het$mean_y) / params$y_sd^2

The global variance is \sigma^2 = 1, and the variance ratio1 is estimated to be 18.99 for the homogeneous-effect setting and 6.8 for the heterogeneous-effect setting (4.36 and 2.61 respectively, on the standard deviation scale).

For the baseline variant, most of the hyperprior parameter specification is trivial to match across engines. However, some hyperpriors are chosen based on the data itself (which can be seen as an empirical Bayes prior).

Tree-structure prior

Naming conventions for the prior on trees differ across packages: alpha = base and beta=power.

These control the prior probability that a node at depth d splits further: P(\text{split at depth } d) = \alpha (1+d)^{-\beta}. These are constants, passed unchanged to whichever argument name each package uses.

Leaf-shrinkage prior

Each leaf’s contribution gets a N(0, \tau^2) prior, with \tau set from k (the number of prior standard deviations a leaf is expected to sit from the boundary of y’s range) and the number of trees:

\tau = \begin{cases} \dfrac{\max(y) - \min(y)}{2k\sqrt{\texttt{n\_trees}}} & \text{if continuous outcome,} \\[8pt] \dfrac{3}{k\sqrt{\texttt{n\_trees}}} & \text{if binary outcome}. \end{cases}

Some differences between packages:

  • BART/dbarts-style engines (including bartCause, which shares dbarts::bart2’s argument set) take \tau via k directly.
  • stochtree standardizes a continuous outcome internally, so it needs the variance \tau^2 on that standardized scale instead. This is \tau^2 / \text{var}(y) for a continuous outcome, or plain \tau^2 for binary (the probit latent isn’t rescaled). stochtree::bcf applies this to both its prognostic and treatment-effect forests.

More generally, BART::wbart and stochtree (both bart and bcf) centre the response before fitting for a continuous outcome (stochtree also rescales it, per the standardisation above), while dbarts::bart2 - and so bartCause, which shares it - works on the raw scale throughout. Neither centering concept applies to the binary outcome, fit directly on the 0/1 response under a probit link in every package here.

Global error-variance prior

Note

The following applies to the real-valued response only.

The residual variance \sigma^2 has an inverse-gamma prior, \sigma^2 \sim \text{Inv-Gamma}(\alpha, \beta), with shape \alpha = \nu / 2 set from \nu = sigdf degrees of freedom.

An intermediate quantity \lambda is calibrated from the data so that the prior places sigquant probability below a rough, data-driven estimate of \sigma itself, giving the scale \beta:

\beta = \frac{\nu \lambda}{2}, \qquad \lambda = \hat\sigma^2 \cdot \frac{\chi^2_{\nu,\,1 - \texttt{sigquant}}}{\nu}, \qquad \hat\sigma = \begin{cases} \hat\sigma_\text{LM-MLE} & \text{if}~n > p,\\ \hat\sigma_y & \text{otherwise}, \end{cases} where \chi^2_{\nu,\,p} is the p-quantile of a \chi^2_\nu distribution, where \hat\sigma_\text{LM-MLE} is the residual SD of a linear fit regressing the response against the covariates, and where \hat\sigma_y is the standard deviation of the data y.

BART/dbarts-style engines compute \hat\sigma, \lambda, and this inverse-gamma prior internally when sigest is left at its default. stochtree has no equivalent auto-calibration of its own - matching it means passing stochtree’s own shape/scale arguments directly, on its internally-standardized scale:

\text{shape} = \alpha = \frac{\nu}{2}, \qquad \text{scale} = \beta_{\text{std}} = \frac{\nu \lambda}{2 \text{var}(y)}.

Package-default hyperprior variants

Every engine has a default version tested, using its own out-of-the-box hyperprior settings other than burn-in, posterior draws, and number of chains remain fixed. stochtree’s warm-start/adaptive-coding settings is also turned off in default and baseline but tested in (+auto_k, +gfr_adaptive_coding). Further details:

  • BART::wbart two-step: no default row for the continuous outcome - BART::wbart’s own defaults already equal baseline.
  • BART::pbart has ntree = 50 by default.
  • stochtree::bart two-step: leaf variance reverts to a sampled, package-default value, and (continuous outcome only) the global error-variance prior reverts to the improper shape = scale = 0.
  • bartc: (based on dbarts::bart2()), has default with n.trees = 75 and k = NULL (auto-tuned, vs fixed at 2) for both the response and treatment model.
  • stochtree::bcf: default version has num_trees/alpha/beta asymmetric between its two forests (250/0.95/2 prognostic, 100/0.25/3 treatment-effect), where baseline explicitly overrides both to the same shared values (see R/hyperparams.R). default reverts both forests to their own separate defaults, on top of the same leaf-variance and global-error-variance reversions as stochtree::bart.

Do CATE draws mix at the same rate across units?

The counterpart of benchmark-prediction.qmd’s “Do the trees mix at the same rate?” - fitted_quantile_acf()/fitted_quantile_draws() (R/metrics.R) are fully generic over the value column, so calling them on cte instead of a raw fitted value tracks the mixing of the treatment-effect distribution across units. Heterogeneous-truth setting only (response_parallel = FALSE) - under the homogeneous truth the CTE quantile spread is pure estimation noise with no structure to compare, the same reasoning already used for the CATE-hat scatter plots above.
