Scope

This document compares predictions from two Bayesian Additive Regression Tree (BART) packages in R that can handle the addition of group-specific random effects. The packages tested are stan4bart and stochtree.

A baseline variant is implemented for engines stan4bart::stan4bart and stochtree::bart. These attempt to match hyperprior specification across the methods, for a fair comparison. Both engines also get a default variant, using their own out-of-the-box priors instead. Note that the global variance term for stan4bart does not have an inverse gamma prior available, unlike most other BART packages, but does have several other choices (see Section 3.3 for more details).

The method stochtree::bart additionally gets a baseline+gfr variant, which uses its own warm-start default layered on top of the matched baseline priors, and - continuous outcome only, since it targets \sigma^2 mixing specifically and \sigma^2 is fixed at 1 for binary - a baseline+thin variant, which extends burn-in by 5x and thins the retained chain by 10x (see Section 5.5 for mixing comparison). The final number of retained draws is T=1000 in all cases.

Data generating process

The benchmarking is performed using Friedman’s function (Friedman 1991) as data-generating process. Friedman’s function is augmented with additive group-specific random intercepts with simulate_friedman_rfx()/simulate_friedman_rfx_binary() (R/dgp.R). The random-intercepts are generated with \sigma^2_G = 9 for continuous case, and \sigma^2_G = 0.25 in the binary case.

For the continuous outcome, independent N(0, \sigma^2) noise is added on top of Friedman’s function plus the group intercepts1.

Signal-to-noise metrics (continuous case)

Two separate identifiability questions (problem difficulty) are relevant to this benchmark: how recoverable is Friedman’s function itself, and how recoverable are the group intercepts? A signal-to-noise ratio approach is used for both, as explained next.

Code 
set.seed(1)
n_snr <- 5000
X_snr <- as.data.frame(matrix(runif(n_snr * 10), ncol = 10))
colnames(X_snr) <- paste0("x", 1:10)
var_friedman <- var(friedman_f(X_snr))

Mean recovery

This treats both the observation noise and the group intercepts as nuisance variance adding difficulty to recovering f(X). The numerator measures Friedman’s function’s variation across simulated covariates. \text{SNR}_\text{mean} = \frac{\text{Var}(f(X))}{\sigma^2 + \sigma_G^2}. This does not account for n\in \{250, 1000\}. Smaller n will also increase the problem difficulty.

Code 
snr_mean <- var_friedman / (params$y_sd^2 + params$sd_group_continuous^2)

The estimated variance of Friedman’s function is 24.07, against a combined nuisance variance of \sigma^2 + \sigma_G^2 = 10, giving a mean-recovery ratio of 2.41, or 1.55 on the standardised scale (square root).

Intercept recovery

This treats both the observation noise and Friedman’s function’s variation across covariates as nuisance variance. \text{SNR}_\text{intercept} = \frac{\sigma_G^2}{\text{Var}(f(X)) + \sigma^2}.

This does not account for \bar{n} = \frac{n}{n_G} \in \{ 10, 40\}. Smaller \bar{n} will also increase the problem difficulty.

Code 
snr_intercept <- params$sd_group_continuous^2 / (var_friedman + params$y_sd^2)

The group-intercept variance is \sigma_G^2 = 9, against a combined nuisance variance of \text{Var}(f(X)) + \sigma^2 = 25.07, giving an intercept-recovery ratio of 0.36, or 0.6 on the standardised scale (square root).

Tree-structure prior

Naming conventions for the prior on trees differ across packages: alpha = base and beta=power.

These control the prior probability that a node at depth d splits further: P(\text{split at depth } d) = \alpha (1+d)^{-\beta}. These are constants, passed unchanged to the correct argument for each package.

Leaf-shrinkage prior

Each leaf’s contribution gets a N(0, \tau^2) prior, with \tau set from k (the number of prior standard deviations a leaf is expected to sit from the boundary of y’s range) and the number of trees:

\tau = \begin{cases} \dfrac{\max(y) - \min(y)}{2k\sqrt{\texttt{n\_trees}}} & \text{continuous outcome - uses the data's own range} \\[8pt] \dfrac{3}{k\sqrt{\texttt{n\_trees}}} & \text{binary outcome - calibrated to the probit latent's } \pm 3 \text{ range instead} \end{cases}

Some differences between packages:

  • stan4bart calculates \tau internally from the user-specified k argument (as with dbarts::bart2).
  • stochtree requires the specification of \tau directly. It also standardizes continuous outcomes internally, so it requires the \tau^2 to be specified on this standardized scale instead — we calculate the standardisation manually with \tau^2 / \text{var}(y).

More generally, stochtree centres continuous responses before fitting (stochtree also rescales it, per the standardisation above), while stan4bart work on the raw scale throughout.

Global error-variance prior

Note

The following applies to the real-valued response only.

Unlike BART/dbarts there is no empirical-Bayes style calibration of the prior for the global noise variance in stochtree or stan4bart. Since we observed such a data-calibrated prior to work well in the vanilla prediction benchmark, we construct this calibrated prior for the baseline variant.

For the baseline variant, the stochtree package supports inverse-gamma priors for the global variance so we can match the BART/dbarts data-calibrated prior exactly. Whereas we develop a special matching procedure for stan4bart using truncated student-t distributions. The details are given below.

Inverse-gamma prior for stochtree

Similar to the vanilla prediction baseline variant for stochtree, we construct the data-calibrated prior of the variance as follows. A crude estimate of the variance is estimated by fitting a linear model against covariates and group-specific random effects (using lme4::lmer if it is available). We denote the residual variance estimate from this model as \hat\sigma^2.

For stochtree the prior needs to be set on the internally-standardized scale it expects for a continuous outcome, and it is specified by with shape/scale arguments. Overall, this specification is

\lambda = \hat\sigma^2 \cdot \frac{\chi^2_{\nu,\,1-\texttt{sigquant}}}{\nu}, \qquad \nu = \texttt{sigdf}, \qquad \text{shape} = \frac{\nu}{2}, \qquad \text{scale} = \frac{\nu\lambda}{2\,\text{var}(y)}, where \chi^2_{\nu,\,p} is the p-quantile of a \chi^2_\nu distribution.

Truncated student-t prior for stan4bart

The stan4bart package specifies the global standard deviation prior via prior_aux, a convenience wrapper that can choose from a fixed set of priors (normal, student_t/cauchy, exponential, hs, hs_plus, laplace, lasso). Given the limited choices it is not possible to match the inverse-gamma distribution (on the variance) exactly.

If \sigma^2 \sim \text{IG}(\alpha, \beta), then \sigma follows a generalised inverse gamma distribution (c = 2 case) with probability density and cumulative density functions

p(\sigma) = \frac{2\beta^{\alpha}}{\Gamma(\alpha)}\, \sigma^{-2\alpha-1} \exp\!\left(-\frac{\beta}{\sigma^{2}}\right), \qquad F(\sigma \le s) = Q\!\left(\alpha,\, \frac{\beta}{s^{2}}\right), where Q is the regularised upper incomplete gamma function. This is the target we will approximate for the stan4bart baseline variant. The mode and tail behaviour of the generalised inverse gamma are:

\text{mode} = \sqrt{\frac{2\beta}{2\alpha+1}}, \qquad p(\sigma) \propto \sigma^{-(\nu+1)} \text{ as } \sigma \to \infty,

with \alpha = \nu/2 and \beta = \nu\lambda/2. We use these features to match against for the truncated Student-t approximation.

The Student-t distribution has three free parameters which we choose as follows.

  • The degrees of freedom is set to \nu. A t_\nu density decays as \sigma^{-(\nu+1)} which matches the generalised inverse gamma tail.
  • The mean of the Student-t is set to \mu = \sqrt{2\beta/(2\alpha+1)}. This matches the mode of the approximation to the target generalised inverse gamma.
  • The scale of the Student-t is chosen so that the one-sided 90% quantile of each target and approximate distribution match.

Note that the truncation to of the Student-t distribution to (0,\infty) is applied automatically by Stan.

Comparison of priors

The default variant, which uses each package’s own out-of-the-box choice:

  • data-calibrated exponential prior for stan4bart on the standard deviation, and
  • stochtree’s default inverse-gamma is a \text{IG}(0,0) distribution (an improper Jeffery’s prior) on the variance.

The stan4bart default is

\sigma \sim \text{Exponential}\!\left(\text{rate} = 1/\text{sd}(y)\right),

whilst stochtree’s default is an improper prior with density p(\sigma^2) \propto \frac{1}{\sigma^2} on the variance, or equivalently

p(\sigma) \propto \frac{1}{\sigma},

on the standard deviation.

The following comparison plots these an example of these priors (minus the improper prior) on the standard deviation scale. The data-calibrated priors are constructed by simulating n = 250 samples and using equivalent settings to the simulation to be performed.

  2 * beta^alpha / gamma(alpha) * y^(-2 * alpha - 1) * exp(-beta / y^2)
}
sigma_trunc_t_density <- function(x, df, location, scale) {
  ifelse(x <= 0, 0,
    dt((x - location) / scale, df = df) / scale / (1 - pt(-location / scale, df = df))
  )
}

Group-effect recovery

Here we look at the recovery of the group-specific intercepts. A BART’s trees can absorb part of the overall baseline level that would otherwise be captured in the random intercepts. That is, the group mean can be split between “trees” and “random intercepts” differently, causing . A raw bias or RMSE would penalise that arbitrary split rather than genuine recovery failure, so both metrics below first remove each side’s own mean, \bar{\hat u} = \frac{1}{n_G}\sum_g \hat u_g and \bar u = \frac{1}{n_G}\sum_g u_g, before comparing:

\texttt{group\_effect\_cor} = \frac{\sum_g (\hat u_g - \bar{\hat u})(u_g - \bar u)}{\sqrt{\sum_g (\hat u_g - \bar{\hat u})^2} \, \sqrt{\sum_g (u_g - \bar u)^2}}

the ordinary Pearson correlation across groups - shift- and scale-invariant by construction, so it checks only whether groups with a larger true effect also get a larger estimated one, in the right order - and

\texttt{group\_effect\_centered\_rmse} = \sqrt{\frac{1}{n_G} \sum_g \Big[(\hat u_g - \bar{\hat u}) - (u_g - \bar u)\Big]^2}

the RMSE between the two centred sequences. This is the stricter of the two: it also penalises wrong relative spacing between groups, not just wrong ranking, while remaining blind to any shift shared by every group - exactly the one degree of freedom that isn’t identifiable in the first place.

A third, uncentred version is reported alongside them for reference:

\texttt{group\_effect\_raw\_rmse} = \sqrt{\frac{1}{n_G} \sum_g \big(\hat u_g - u_g\big)^2}

the plain RMSE, with no shift removed. This is the “pure recovery” number in the most literal sense - it is what you’d report if the shift were identifiable - but for exactly the reason above, a gap between this and the centred RMSE is expected here and is not, by itself, evidence of worse estimation: it also reflects however much of the baseline level a given engine’s trees happened to absorb. Read it alongside the centred RMSE, not as a replacement for it.

stan4bart’s underlying Stan program does support a genuine fixed global intercept (gated by a has_intercept flag), currently unused here since the fitted formula leaves no fixed-effects term for it to attach to - enabling it is a natural variant to explore in future work.

A synthetic check makes the distinction concrete: take a set of true group effects, then simulate “estimates” that are a known constant shift away from the truth plus a little noise - the kind of gap a real engine could produce by parking part of the baseline in its trees rather than the random intercepts.

Code 
set.seed(1)
demo_true <- rnorm(20, sd = 3)
demo_shift <- 5
demo_hat <- demo_true + demo_shift + rnorm(20, sd = 0.5)
demo_metrics <- group_effect_recovery(demo_hat, demo_true)

With a shift of 5 and noise SD 0.5 on top of it, group_effect_cor = 0.987 (essentially unaffected by the shift - it only sees the noise), group_effect_centered_rmse = 0.425 (recovers that same noise level once the shift is removed), and group_effect_raw_rmse = 5.015 (dominated by the shift itself, close to 5) - exactly the pattern described above.

MCMC mixing

Two engines can have equally sensible priors and equally unbiased posterior means, yet still disagree on prediction accuracy if one’s chain is more autocorrelated: the same nominal number of post-burn-in draws then buys less information, so the posterior mean is noisier - a sampler-efficiency gap rather than a modelling one. This was investigated directly because stan4bart’s baseline variant consistently outperformed stochtree::bart’s on continuous-outcome prediction RMSE, at a gap that did not shrink between the smallest and largest n tested - the tree and random-effects priors were checked first and ruled out (both engines recover \sigma_G and Friedman’s function equally well on average), before this diagnostic surfaced a real, persistent difference in effective sample size (ESS) for the same nominal draw count.

Two parameters are tracked, since a single global one won’t cover both outcomes:

  • \sigma, the global residual SD - continuous outcome only, since it’s fixed at 1 under both engines’ probit link for a binary outcome (confirmed empirically: neither engine even exposes the parameter for a binary fit). Tracked on the SD scale for both engines rather than each package’s own native parameterization: stan4bart’s aux is already on this scale, but stochtree’s own sigma2_global_samples is the variance - comparing them as-is was a real bug (confirmed empirically: stan4bart’s raw draws track sqrt() of stochtree’s, not stochtree’s raw draws), silently comparing an SD against a variance rather than the same quantity.
  • \sigma_G, the random-intercept SD - sampled for both outcomes, and so the substitute diagnostic for the binary case specifically.

Do the trees mix at the same rate?

Both engines update their residual-variance parameter conditional on the current tree ensemble every sweep - confirmed by reading both packages’ own sampling loops, this is blocked-Gibbs alternation on both sides regardless of whether the non-tree update is a Stan HMC step or a conjugate Gibbs draw. That makes the tree ensemble’s own mixing rate a shared candidate bottleneck, which sigma alone can’t distinguish from a problem specific to sigma’s own update. Tracked here via five quantiles (0.05, 0.2, 0.5, 0.8, 0.95) of the fitted values across observations, computed per retained draw - five extra per-draw time series alongside sigma, using the same draws already extracted for RMSE/coverage/CRPS.
